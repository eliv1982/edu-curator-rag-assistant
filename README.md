# EduCurator AI — RAG-ассистент куратора учебного курса

AI-ассистент на основе Retrieval-Augmented Generation для вымышленного курса **«AI Skills Starter Course — стартовый курс по AI-инструментам и prompt engineering»**. Учебный MVP на Streamlit с использованием OpenAI, LangChain и FAISS.

---

## Цель проекта

EduCurator AI — учебный проект, демонстрирующий, как RAG и prompt engineering можно объединить для создания практичного ассистента куратора. Ассистент помогает студентам ориентироваться в материалах курса, понимать концепции, находить ресурсы и получать ответы на организационные вопросы — не галлюцинируя и не выходя за рамки своей роли.

---

## Бизнес-задачи

- Снизить нагрузку на куратора-человека, автоматически отвечая на типовые вопросы
- Обеспечить студентам поддержку 24/7 вне зависимости от часового пояса
- Продемонстрировать ответственный дизайн AI-ассистента: честный, опирающийся на источники, с чёткими границами компетенции
- Служить учебным артефактом для курса по prompt engineering

---

## Функциональность

| Функция | Описание |
|---------|---------|
| **RAG Q&A** | Ответы на вопросы, основанные на проиндексированной базе знаний курса |
| **Адаптация к уровню** | Подстройка сложности ответа для начинающих и продвинутых студентов |
| **Ссылки на источники** | Показывает, какие документы были использованы при ответе |
| **Вкладка «Курс»** | Описание курса и таблица заданий с дедлайнами |
| **Вкладка «Аналитика»** | Статистика запросов: всего, по уровню, по теме, последние вопросы |
| **Логирование** | Каждый вопрос записывается в `logs/query_log.csv` |
| **Честный fallback** | Признаёт отсутствие информации вместо того чтобы выдумывать |

## Как запустить локально

### 1. Клонировать или скачать проект

```bash
git clone <repo-url>
cd edu-curator-rag-assistant
```

### 2. Создать виртуальное окружение

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# macOS/Linux
source venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Создать файл `.env`

```bash
cp .env.example .env
```

Отредактируйте `.env` и добавьте ваш ключ OpenAI API:

```
OPENAI_API_KEY=sk-ваш-реальный-ключ
OPENAI_MODEL=gpt-4o-mini
RAG_TOP_K=4
```

### 5. Запустить приложение

```bash
streamlit run app.py
```

Приложение откроется по адресу `http://localhost:8501`.

При первом запуске FAISS-индекс построится автоматически (~15–30 секунд).

## Как обновить базу знаний

1. Отредактируйте `.md`-файлы в `data/` или измените строки в `data/assignments.csv`
   (в `.md`-файлах сохраняйте блок метаданных в начале)
2. Удалите `storage/faiss_index/` для принудительного пересоздания индекса:
   ```powershell
   # Windows PowerShell
   Remove-Item -Recurse -Force storage\faiss_index\
   ```
   ```bash
   # macOS/Linux
   rm -rf storage/faiss_index/
   ```
3. Перезапустите приложение — индекс пересоздастся автоматически (~15–30 сек)

> **Важно:** при любых изменениях в `assignments.csv` (например, обновлении дедлайнов) также необходимо удалить и пересоздать индекс.

Подробности — в `docs/update_guide.md`.

## Как работает RAG

### Построение индекса

При запуске индексируются два типа источников:

**Markdown-файлы** из `data/` (кроме `few_shot_examples.md`):
- разбиваются на чанки (800 токенов, перекрытие 100) через `RecursiveCharacterTextSplitter`
- метаданные берутся из заголовка файла: `source`, `resource_type`, `module`, `topic`

**`data/assignments.csv`** — LMS-заглушка с заданиями и дедлайнами:
- каждая строка преобразуется в отдельный `Document`
- текст содержит модуль, задание, дедлайн, статус и описание в читаемом виде
- метаданные:

| Поле | Значение |
|------|---------|
| `source` | `assignments.csv` |
| `resource_type` | `lms_stub` |
| `topic` | `deadlines` |
| `module` | значение колонки `module` |

Все документы встраиваются с помощью `text-embedding-3-small` и сохраняются в `storage/faiss_index/`.

### Retrieval при вопросе

1. Вопрос студента встраивается тем же эмбеддингом
2. **Приоритетный контекст:** если вопрос содержит слова о дедлайнах или заданиях (`дедлайн`, `срок`, `задани`, `сдать`, `модуль` и др.), данные из `assignments.csv` добавляются в начало контекста детерминированно — до семантического поиска. Это гарантирует, что LLM видит точные даты и не игнорирует их
3. Из FAISS-индекса извлекаются top-K наиболее похожих чанков (по умолчанию 4)
4. Все чанки объединяются и подставляются в системный промпт как `{context}`
5. LLM генерирует ответ, опираясь на найденный материал
6. UI показывает ответ и имена исходных файлов-источников

Полная схема — в `docs/rag_schema.md`.

## Как работает логирование и аналитика

- Каждый вопрос добавляется в `logs/query_log.csv` (создаётся автоматически)
- Записываемые поля: `timestamp`, `question`, `learner_level`, `retrieved_sources`, `answer_preview`, `topic_guess`
- `topic_guess` определяется по ключевым словам: дедлайны, задания, rag, промпты, ресурсы, общее
- Вкладка **«Аналитика»** читает этот файл и отображает:
  - Общее количество вопросов
  - Разбивку по уровню студента
  - Разбивку по теме
  - Последние 10 вопросов

## Возможное масштабирование проекта

Учебный MVP можно развивать в полноценного ассистента для образовательной платформы. Возможные направления:

- **Интеграция с LMS**: подключить реальные данные о курсах, заданиях, дедлайнах и статусах студентов через API вместо локального CSV-файла.
- **Авторизация и роли пользователей**: разделить доступ для студентов, кураторов, преподавателей и администраторов.
- **История диалога и персонализация**: учитывать предыдущие вопросы студента, уровень подготовки, прогресс по модулям и частые затруднения.
- **Админ-интерфейс для обновления базы знаний**: дать кураторам возможность загружать новые материалы и переиндексировать базу без ручного удаления FAISS-индекса.
- **Расширенная аналитика**: собирать частые темы вопросов, проблемные модули, повторяющиеся запросы и использовать эти данные для улучшения курса.
- **Мультимодальный интерфейс**: добавить Telegram-бота, виджет для сайта или интеграцию во внутренний кабинет образовательной платформы.
- **Контроль качества ответов**: добавить набор тестовых вопросов, регулярную проверку ответов и метрики качества retrieval/generation.
- **Эскалация к человеку**: автоматически формировать обращение к куратору, если вопрос выходит за рамки базы знаний или требует индивидуального решения.

Эти улучшения не входят в текущий учебный MVP, но показывают, как проект может быть развит в практический продукт для онлайн-школы или корпоративной образовательной платформы.

## Ограничения учебного MVP

- Ассистент **не помнит** предыдущие диалоги — каждый вопрос независим
- База знаний **статична** — изменения требуют ручного пересоздания индекса
- **Нет авторизации** — любой, у кого есть доступ к URL, может использовать ассистента
- **Нет реальной LMS-интеграции** — дедлайны и задания — вымышленные данные в CSV
- **Уровень студента** основан на самооценке, а не на реальном тестировании
- **Только русский язык** — база знаний и промпты на русском
- Стоимость API: примерно $0.001–0.003 за вопрос при использовании gpt-4o-mini

## Сценарии для проверки перед сдачей

Задайте эти вопросы в приложении и убедитесь, что ответы корректны.

### Объяснение концепций (уровень «Начинающий»)

> «Что такое токен? Объясни простыми словами.»

Ожидаемое поведение: понятное объяснение с аналогией, без жаргона. Источник — `modules.md`.

> «Я новичок. Объясни, что такое RAG и зачем он нужен.»

Ожидаемое поведение: доступное объяснение Retrieval-Augmented Generation с примером. Источник — `modules.md`.

### Углублённый запрос (уровень «Продвинутый»)

> «Я продвинутый студент. Какие дополнительные материалы посмотреть по RAG?»

Ожидаемое поведение: ссылки на статьи (Lewis et al. 2020), LlamaIndex, RAGAS из `resources.md`. Технический тон ответа.

### Вопросы о дедлайнах и заданиях

> «Когда дедлайн по заданию модуля 4?»

Ожидаемое поведение: ответ с точной датой **2026-07-05** из `assignments.csv`. Источник — `assignments.csv (deadlines)`.

> «Что делать, если я не успеваю сдать задание вовремя?»

Ожидаемое поведение: описание окна опозданий (3 дня, −10%/день), инструкция по запросу переноса, email куратора. Источник — `faq.md`.

### Проверка границ: информация вне базы знаний

> «Кто ведущий преподаватель курса?»

Ожидаемое поведение: честное «В материалах курса я не нашёл этой информации» + предложение обратиться к куратору. Никаких выдуманных имён.

### Проверка ограничений ассистента

> «Можешь изменить мне дедлайн по заданию?»

Ожидаемое поведение: вежливый отказ («я не могу менять дедлайны»), инструкция написать куратору минимум за 24 часа.

> «Поставь мне зачёт за модуль 2.»

Ожидаемое поведение: вежливый отказ («я не выставляю оценки»), объяснение как работает оценивание, направление к куратору.
