# Архитектура промптов — EduCurator AI

## Обзор

Этот документ описывает дизайн промптов для AI-ассистента EduCurator: роль ассистента, сценарии диалогов, ограничения, адаптацию к уровню студента и few-shot подход.

---

## 1. Роль ассистента

EduCurator — это **ассистент в обучении**, а не учитель, не репетитор и не администратор. Его роль чётко ограничена:

| В компетенции | Вне компетенции |
|---------------|----------------|
| Объяснять концепции курса | Выставлять оценки |
| Отвечать на вопросы из FAQ | Менять дедлайны |
| Рекомендовать ресурсы | Получать доступ к данным студента |
| Описывать требования к заданиям | Решать задания за студента |
| Направлять к живой поддержке | Принимать административные решения |

Ассистент спроектирован как **первая точка контакта** для студентов — до обращения к куратору-человеку.

---

## 2. Структура промпта

Каждый запрос к LLM состоит из трёх частей:

```
[Системный промпт]
  └─ Определение роли
  └─ Инструкция по уровню студента
  └─ Найденный контекст курса (RAG)
  └─ Правила поведения и ограничения

[Сообщение пользователя]
  └─ Вопрос студента (как введён)

[Ответ ассистента]
  └─ Ответ, основанный на материалах курса
  └─ Ссылки на источники
  └─ Эскалация при необходимости
```

Системный промпт собирается динамически в `src/prompt_builder.py` путём подстановки:
1. `{learner_level}` — «beginner» или «advanced», выбирается студентом
2. `{context}` — чанки, найденные в FAISS-индексе по запросу

## 3. Основные сценарии

### Сценарий А: Объяснение концепции

**Триггер:** студент спрашивает «Что такое chain-of-thought промптинг?»
**Пайплайн:**
1. RAG находит чанки из `modules.md` (Модуль 3) и `resources.md`
2. Системный промпт задаёт тон в зависимости от уровня
3. LLM объясняет концепцию, опираясь на найденный материал
4. Ответ содержит ссылки на источники

### Сценарий Б: Вопрос о дедлайне

**Триггер:** студент спрашивает «Когда дедлайн по заданию модуля 4?»
**Пайплайн:**
1. RAG находит чанки из `modules.md` и `faq.md`
2. LLM извлекает дату дедлайна и политику опозданий
3. Ответ содержит дедлайн и контекст с политикой

### Сценарий В: Рекомендация ресурсов

**Триггер:** студент спрашивает «Что почитать, чтобы глубже изучить RAG?»
**Пайплайн:**
1. RAG находит чанки из `resources.md`
2. Системный промпт применяет фильтр уровня (beginner / advanced)
3. LLM рекомендует подходящие ресурсы с пояснением

### Сценарий Г: Запрос вне компетенции

**Триггер:** студент просит «Измени мою оценку»
**Пайплайн:**
1. RAG ничего не находит по теме (или находит FAQ об оценках)
2. LLM применяет правила ограничений из системного промпта
3. Ответ вежливо отклоняет запрос и направляет к куратору-человеку

### Сценарий Д: Неизвестная тема

**Триггер:** студент спрашивает о чём-то, чего нет в базе знаний
**Пайплайн:**
1. RAG извлекает нерелевантные чанки (низкое сходство) или ничего
2. LLM честно сообщает: «В материалах курса этого нет»
3. Предлагает помощь по смежным темам или советует обратиться к куратору

## 4. Ограничения и защитные правила

Системный промпт явно запрещает:

1. **Запрет галлюцинаций** — «не выдумывай информацию вне материалов курса»
2. **Запрет обещать результат** — «не обещай зачёт, сертификат или конкретную оценку»
3. **Запрет менять дедлайны** — «не меняй дедлайны»
4. **Запрет решать задания** — «не давай прямых ответов на задания»
5. **Обязательные источники** — «всегда указывай источники, если использованы материалы курса»
6. **Обязательная эскалация** — определены условия передачи вопроса куратору-человеку

Эти ограничения применяются через системный промпт и верифицируются примерами из `few_shot_examples.md`.

## 5. Адаптация под уровень студента

Ассистент адаптирует ответ на основе параметра `learner_level`:

### Режим «Начинающий» (beginner)
- Использовать простой язык, избегать жаргона
- Давать аналогии и примеры из жизни
- При первом употреблении определять технические термины
- Больше поддержки и ободрения
- Рекомендовать ресурсы из раздела «Для начинающих» в `resources.md`
- Ответы короче и сфокусированнее

### Режим «Продвинутый» (advanced)
- Свободно использовать техническую терминологию
- Пропускать базовые определения
- При необходимости ссылаться на научные статьи
- Предлагать сложные ресурсы и фреймворки
- Признавать тонкости и компромиссы в тематике
- Допускать упоминание ограничений и открытых исследовательских вопросов

Уровень подставляется в системный промпт через переменную `{learner_level}`.

## 6. Few-shot подход

Ассистенту не передаётся классический few-shot блок в каждом вызове API (это слишком затратно по токенам). Вместо этого примеры в `data/few_shot_examples.md` выполняют две функции:

1. **Руководство по разработке** — примеры определяют ожидаемое поведение при итерации и тестировании промпта
2. **RAG-контекст** — `few_shot_examples.md` индексируется в FAISS наряду с другими материалами. Если студент задаёт мета-вопрос о поведении ассистента, релевантные примеры могут быть найдены как контекст

Такой подход сохраняет эффективность по токенам, при этом обеспечивая согласованность поведения, закреплённую в явных примерах.

---

## 7. Бюджет токенов

Примерное распределение токенов на один запрос:

| Компонент | Примерное число токенов |
|-----------|------------------------|
| Системный промпт (базовый) | ~600 |
| Инструкция по уровню | ~60 |
| RAG-контекст (4 чанка × ~300 токенов) | ~1 200 |
| Вопрос студента | ~50–150 |
| **Итого вход** | **~1 910–2 010** |
| Ответ (цель) | ~300–600 |
| **Итого на запрос** | **~2 210–2 610** |

С моделью `gpt-4o-mini` это примерно $0.001–0.003 за вопрос по текущим тарифам.

---

## 8. Известные ограничения

- Ассистент не имеет памяти между сессиями (без сохранения состояния)
- Все знания статичны — база знаний требует ручного обновления
- Качество RAG-поиска зависит от качества чанков и сходства эмбеддингов
- Ассистент не может верифицировать личность студента или получить доступ к данным платформы
- Адаптация уровня основана на самооценке студента, а не на реальном тестировании
