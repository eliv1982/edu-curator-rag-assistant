# Руководство по обновлению — база знаний EduCurator AI

## Обзор

Это руководство объясняет, как обновлять базу знаний курса, когда нужно пересоздавать FAISS-индекс и как безопасно изменять системный промпт и инструкции ассистента.

---

## 1. Редактирование Markdown-файлов

### Когда обновлять

Обновляйте Markdown-файлы в `data/`, когда:
- Меняется структура курса или относительные сроки («конец 3-й недели») — `modules.md` и `faq.md` (точные даты задаются в `assignments.csv`, см. раздел 2)
- Добавляются новые модули или темы (`modules.md`)
- Выявляются новые частые вопросы (`faq.md`)
- Появляются новые внешние ресурсы (`resources.md`)

Файл `few_shot_examples.md` (примеры поведения ассистента) в индекс не входит и в промпт не подставляется — это справочный материал. Его правка не требует пересоздания индекса и сама по себе не меняет поведение приложения.

### Как редактировать Markdown-файл

1. Откройте нужный файл в `data/`
2. Внесите изменения
3. **Всегда сохраняйте блок метаданных в начале файла:**

```markdown
# Название документа

**source:** filename.md
**resource_type:** [overview|curriculum|faq|resources|examples]
**module:** [название модуля или "general" или "all"]
**topic:** [тег темы]
```

4. Сохраните файл
5. **Пересоздайте FAISS-индекс** (см. раздел 3 ниже)

### Допустимые значения полей метаданных

| Поле | Допустимые значения |
|------|---------------------|
| `resource_type` | `overview`, `curriculum`, `faq`, `resources`, `examples` |
| `module` | `module_1`…`module_6`, `general`, `all` |
| `topic` | `course_info`, `modules`, `deadlines`, `assignments`, `rag`, `prompts`, `resources`, `general` |

## 2. Обновление CSV с заданиями

Файл `data/assignments.csv` используется в трёх местах:

- **FAISS-индекс.** Каждая строка CSV превращается в документ и индексируется вместе с Markdown-файлами.
- **Детерминированный путь.** Для вопросов о дедлайнах и заданиях приложение читает CSV напрямую при каждом вопросе и ставит эти данные в начало контекста.
- **Вкладка «Курс».** Таблица заданий читается из CSV при отрисовке вкладки.

Поэтому после изменения CSV существующий FAISS-индекс **устаревает**: вкладка «Курс» и детерминированный путь сразу показывают новые данные, а копии строк в индексе остаются прежними и могут попасть в контекст через семантический поиск рядом с новыми.

### Формат CSV

```csv
module,assignment,deadline,status,description
Модуль 1,Название задания,ГГГГ-ММ-ДД,Открыто,"Текст описания"
```

Колонка `status` — свободный текст: приложение не интерпретирует её значения, а только показывает и передаёт модели. В демо-данных используется значение `Открыто`. Колонка `deadline` — тоже текст: код не проверяет формат даты, но системный промпт ожидает вид `ГГГГ-ММ-ДД`.

Демо-даты в репозитории вымышлены и могут быть в прошлом: приложение не сверяет их с текущей датой.

### Как обновить дедлайны

1. Откройте `data/assignments.csv`
2. Измените поле `deadline` (формат: `ГГГГ-ММ-ДД`)
3. Сохраните файл
4. **Пересоздайте FAISS-индекс** (см. раздел 3) и перезапустите приложение

## 3. Пересоздание FAISS-индекса

FAISS-индекс нужно пересоздавать каждый раз, когда вы:
- Добавляете новый `.md`-файл в `data/`
- Редактируете существующие `.md`-файлы (индекс не отражает изменения автоматически)
- Изменяете `assignments.csv` (строки CSV входят в индекс)
- Удаляете документ из `data/`

Изменение только `few_shot_examples.md` пересоздания не требует — он не индексируется.

### Как пересоздать

**Вариант А: Автоматически (рекомендуется)**
Удалите файлы индекса и перезапустите приложение — оно пересоздаст индекс само:

```bash
# Удалить индекс (macOS/Linux)
rm -rf storage/faiss_index/

# Перезапустить приложение
streamlit run app.py
```

На Windows (PowerShell):
```powershell
Remove-Item -Recurse -Force storage\faiss_index\
streamlit run app.py
```

**Вариант Б: Ручное пересоздание через Python**
```python
from src.rag_pipeline import build_index
build_index()
```

Запускайте из корня репозитория (пути в коде относительные); переменная `OPENAI_API_KEY` должна быть задана в окружении — файл `.env` подхватывается только в `app.py`. Уже запущенное приложение держит старый индекс в кэше, поэтому его нужно перезапустить.

### Сколько времени занимает пересоздание?

Для текущей базы знаний (4 индексируемых `.md`-файла и 6 строк `assignments.csv`) пересоздание занимает около 10–30 секунд в зависимости от скорости интернет-соединения (требуются вызовы OpenAI Embeddings API).

## 4. Обновление системного промпта

Системный промпт реализован в коде: переменная `SYSTEM_PROMPT_TEMPLATE` в `src/prompt_builder.py` — единственный авторитетный источник. Функция `build_system_prompt()` подставляет в него контекст и уровень студента. Файл `docs/system_prompt.md` содержит только описание структуры и поведения промпта и указатель на код; копии текста промпта в документации нет.

### Как обновить промпт

1. Отредактируйте шаблон в `src/prompt_builder.py` в переменной `SYSTEM_PROMPT_TEMPLATE`
2. Если изменились роль, правила или структура промпта, обновите описание в `docs/system_prompt.md` и, при необходимости, `docs/prompt_architecture.md`
3. Протестируйте изменения на представительных запросах (см. сценарии в `README.md`) перед развёртыванием

### На что обратить внимание

- Сохраняйте плейсхолдеры `{context}` и `{learner_level}` — они обязательны; шаблон заполняется через `str.format()`, поэтому любые другие фигурные скобки в тексте нужно удваивать (`{{` и `}}`)
- Следите за длиной: сейчас шаблон занимает порядка 900 токенов (оценка для токенайзера `o200k_base`) без контекста; оставляйте место для найденных чанков и ответа (`max_tokens=800`)
- Всегда проверяйте, что ограничительные правила по-прежнему работают (попробуйте попросить ассистента изменить дедлайн)
- Поддерживайте актуальность пути эскалации (email куратора)

---

## 5. Добавление нового типа документа

Если нужно добавить новый тип документа (например, транскрипты лекций, конспекты видео):

1. Создайте `.md`-файл в `data/` со стандартным блоком метаданных
2. Выберите подходящие значения `resource_type` и `topic` (или добавьте новые)
3. Обновите `docs/rag_schema.md`, задокументировав новый тип
4. Пересоздайте FAISS-индекс
5. Протестируйте поиск на представительных запросах

## 6. Управление логами

Логи запросов хранятся в `logs/query_log.csv`. Файл растёт со временем.

### Архивирование старых логов

```bash
# Переименовать старый лог и начать с чистого
mv logs/query_log.csv logs/query_log_archive_2024_Q1.csv
```

Приложение автоматически создаст новый `query_log.csv` при следующем запросе.

### Формат лога

```csv
timestamp,question,learner_level,retrieved_sources,answer_preview,topic_guess
```

Колонка `retrieved_sources` содержит найденные материалы (те, что переданы модели в контексте), а не подтверждённые источники ответа.

Журнал не записывает идентификаторы пользователей, но вопросы сохраняются как свободный текст и могут содержать личные данные, если студент их напишет. Авторизации в приложении нет: вкладка «Аналитика» открыта всем, кто видит приложение.

## 7. Чеклист безопасности перед публикацией изменений

Перед публикацией изменений в общей среде проверьте:

- [ ] Файлы `.env` и `.streamlit/secrets.toml` не попали в коммит (проверьте `.gitignore`)
- [ ] API-ключи отсутствуют в исходных файлах
- [ ] Блоки метаданных присутствуют во всех `.md`-файлах
- [ ] FAISS-индекс пересоздан после изменения индексируемого контента (`.md`-файлы и `assignments.csv`)
- [ ] Ограничения системного промпта по-прежнему работают
- [ ] Приложение запускается без ошибок (`streamlit run app.py`)
- [ ] Минимум 3 тестовых запроса возвращают осмысленные ответы
- [ ] `requirements.txt` отражает все новые зависимости
