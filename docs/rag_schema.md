# Схема RAG — EduCurator AI

## Обзор

Этот документ описывает архитектуру Retrieval-Augmented Generation (RAG): источники данных, структуру метаданных, FAISS-индекс и поток поиска.

---

## 1. Источники данных

Все документы базы знаний хранятся в директории `data/`.

| Файл | Тип | Содержание |
|------|-----|-----------|
| `course_overview.md` | Обзор | Описание курса, цели, формат, сертификация |
| `modules.md` | Учебный план | 6 модулей с описаниями тем и краткими описаниями заданий |
| `faq.md` | FAQ | Дедлайны, оценки, технические вопросы, сообщество |
| `resources.md` | Ресурсы | Внешние учебные ресурсы по уровню и модулям |
| `few_shot_examples.md` | Примеры | Примеры корректного и некорректного поведения ассистента |

`assignments.csv` используется только для отображения в разделе «Курс» и **не индексируется** в FAISS (это структурированные данные, не подходящие для семантического поиска).

---

## 2. Метаданные документов

Каждый Markdown-файл содержит заголовочный блок метаданных в начале. Эти значения разбираются при построении индекса и прикрепляются к каждому чанку как метаданные документа LangChain.

### Поля метаданных

| Поле | Тип | Описание | Пример |
|------|-----|---------|--------|
| `source` | строка | Имя исходного файла | `modules.md` |
| `resource_type` | строка | Тип контента | `curriculum`, `faq`, `overview`, `resources`, `examples` |
| `module` | строка | Какому модулю принадлежит контент | `module_5`, `general`, `all` |
| `topic` | строка | Тег темы для аналитики | `rag`, `deadlines`, `resources`, `general` |

### Пример блока метаданных в Markdown

```markdown
# Название документа

**source:** modules.md
**resource_type:** curriculum
**module:** all
**topic:** modules
```

### Разбор метаданных

Метаданные разбираются в `src/rag_pipeline.py` простым поиском регулярным выражением по первым 15 строкам каждого документа. Если поля метаданных отсутствуют, значения по умолчанию берутся из имени файла.

---

## 3. Разбивка текста на чанки

Документы разбиваются на чанки перед эмбеддингом.

| Параметр | Значение | Обоснование |
|----------|---------|-------------|
| Размер чанка | 800 токенов | Баланс между богатством контекста и шумом |
| Перекрытие чанков | 100 токенов | Предотвращает потерю контекста на границах чанков |
| Сплиттер | `RecursiveCharacterTextSplitter` | Уважает границы абзацев и предложений |

Каждый чанк наследует метаданные родительского документа.

---

## 4. Эмбеддинги

| Параметр | Значение |
|----------|---------|
| Модель | `text-embedding-3-small` (OpenAI) |
| Размерность | 1536 |
| Провайдер | OpenAI Embeddings API |

Модель эмбеддингов вызывается через `OpenAIEmbeddings` из `langchain-openai`.

---

## 5. FAISS-индекс

FAISS-индекс хранится локально в `storage/faiss_index/`.

| Файл | Описание |
|------|---------|
| `index.faiss` | FAISS-индекс векторов |
| `index.pkl` | Сериализованное хранилище документов: маппинг ID чанков на текст и метаданные |

Индекс строится автоматически при первом запуске, если его нет. Для ручного пересоздания удалите `storage/faiss_index/` и перезапустите приложение.

---

## 6. Поток поиска

```
Вопрос студента
       │
       ▼
OpenAI Embeddings API
(эмбеддинг вопроса)
       │
       ▼
FAISS similarity_search()
(косинусное сходство, top_k=4 по умолчанию)
       │
       ▼
Найденные чанки
(текст + метаданные для каждого)
       │
       ▼
Сборка контекста
(объединение текстов чанков, сбор имён источников)
       │
       ▼
Построитель промпта
(подстановка контекста + learner_level в системный промпт)
       │
       ▼
OpenAI Chat API
(gpt-4o-mini по умолчанию)
       │
       ▼
Ответ + источники отображаются в UI
```

---

## 7. Параметры поиска

| Параметр | По умолчанию | Env-переменная | Описание |
|----------|-------------|----------------|---------|
| `top_k` | 4 | `RAG_TOP_K` | Количество извлекаемых чанков |
| Модель | `gpt-4o-mini` | `OPENAI_MODEL` | LLM для генерации ответа |
| Эмбеддинги | `text-embedding-3-small` | (задано в коде) | Модель эмбеддингов |

---

## 8. Добавление новых документов

Чтобы добавить новый документ в базу знаний:

1. Создайте `.md`-файл в `data/` с блоком метаданных в начале
2. Удалите `storage/faiss_index/` для принудительного пересоздания индекса
3. Перезапустите приложение — индекс будет пересоздан автоматически

Подробные инструкции — в `docs/update_guide.md`.

---

## 9. Ограничения

- Индексируются только `.md`-файлы в `data/` (не поддиректории)
- Пересоздание индекса требует перезапуска приложения (горячая перезагрузка не поддерживается)
- Нет гибридного поиска (ключевые слова + векторный) — только семантический
- Качество поиска зависит от качества модели эмбеддингов
- Очень короткие или плохо написанные чанки могут плохо находиться
