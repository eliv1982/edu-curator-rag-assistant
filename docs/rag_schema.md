# Схема RAG — EduCurator AI

## Обзор

Этот документ описывает архитектуру Retrieval-Augmented Generation (RAG): источники данных, структуру метаданных, FAISS-индекс и поток поиска. Реализация — в `src/rag_pipeline.py`; при расхождении документа и кода верен код.

---

## 1. Источники данных

Все документы базы знаний хранятся в директории `data/`.

| Файл | Тип | Содержание | В FAISS-индексе |
|------|-----|-----------|:---------------:|
| `course_overview.md` | Обзор | Описание курса, цели, формат, сертификация | да |
| `modules.md` | Учебный план | 6 модулей с описаниями тем и краткими описаниями заданий | да |
| `faq.md` | FAQ | Дедлайны, оценки, технические вопросы, сообщество | да |
| `resources.md` | Ресурсы | Внешние учебные ресурсы по уровню и модулям | да |
| `assignments.csv` | Задания (LMS-заглушка) | Модуль, задание, дедлайн, статус, описание | да, по одному документу на строку |
| `few_shot_examples.md` | Примеры | Примеры корректного и некорректного поведения ассистента | **нет** |

### `assignments.csv`

Структурированные данные о заданиях используются двумя путями:

1. **Индексация.** При построении индекса каждая строка CSV превращается в отдельный `Document` и попадает в FAISS наряду с чанками Markdown-файлов (`_load_assignments_as_documents()`).
2. **Детерминированный путь.** Если вопрос похож на вопрос о дедлайнах или заданиях (`detect_assignment_query()`), `get_assignment_context()` читает CSV напрямую и ставит эти данные в начало контекста — перед результатами семантического поиска.

Поэтому изменение `assignments.csv` делает уже построенный FAISS-индекс устаревшим: детерминированный путь и вкладка «Курс» увидят новые значения сразу, а копии строк в индексе останутся прежними до пересоздания индекса (см. раздел 5).

### `few_shot_examples.md`

Файл исключён из индексации (`SKIP_FILES` в `src/rag_pipeline.py`) и не подставляется в системный промпт. Сейчас это справочный материал с примерами желаемого и нежелательного поведения. Рантайм-поведение ассистента через эти примеры не проверяется.

## 2. Метаданные документов

Каждый Markdown-файл содержит заголовочный блок метаданных в начале. Эти значения разбираются при построении индекса и прикрепляются к каждому чанку как метаданные документа LangChain.

### Поля метаданных

| Поле | Тип | Описание | Пример |
|------|-----|---------|--------|
| `source` | строка | Имя исходного файла | `modules.md` |
| `resource_type` | строка | Тип контента | `curriculum`, `faq`, `overview`, `resources`, `lms_stub` |
| `module` | строка | Какому модулю принадлежит контент | `module_5`, `general`, `all` |
| `topic` | строка | Тег темы | `rag`, `deadlines`, `resources`, `general` |

Документы из `assignments.csv` получают метаданные `source=assignments.csv`, `resource_type=lms_stub`, `topic=deadlines`, а также `module` и `assignment` из соответствующих колонок.

### Пример блока метаданных в Markdown

```markdown
# Название документа

**source:** modules.md
**resource_type:** curriculum
**module:** all
**topic:** modules
```

### Разбор метаданных

Метаданные разбираются в `src/rag_pipeline.py` простым поиском регулярным выражением по первым 15 строкам каждого документа. Если поле в файле отсутствует, `source` берётся из имени файла, а `resource_type`, `module` и `topic` получают значение `general`.

## 3. Разбивка текста на чанки

Markdown-документы разбиваются на чанки перед эмбеддингом. Размеры заданы в **символах**, а не в токенах: `RecursiveCharacterTextSplitter` использует длину строки в символах.

| Параметр | Значение | Обоснование |
|----------|---------|-------------|
| Размер чанка | 800 символов | Баланс между богатством контекста и шумом |
| Перекрытие чанков | 100 символов | Предотвращает потерю контекста на границах чанков |
| Сплиттер | `RecursiveCharacterTextSplitter` | Уважает границы абзацев и предложений |

Каждый чанк наследует метаданные родительского документа. Строки `assignments.csv` на чанки не разбиваются — одна строка равна одному документу.

---

## 4. Эмбеддинги

| Параметр | Значение |
|----------|---------|
| Модель | `text-embedding-3-small` (OpenAI) |
| Размерность | 1536 |
| Провайдер | OpenAI Embeddings API |

Модель эмбеддингов вызывается через `OpenAIEmbeddings` из `langchain-openai`.

## 5. FAISS-индекс

FAISS-индекс хранится локально в `storage/faiss_index/` и не входит в git.

| Параметр | Значение |
|----------|---------|
| Тип индекса | `IndexFlatL2` (создаётся оболочкой LangChain `FAISS.from_documents` с настройками по умолчанию) |
| Метрика | евклидово расстояние (L2); чем меньше значение, тем ближе чанк к вопросу |
| Поиск | точный, полным перебором (без приближённых индексов) |

| Файл | Описание |
|------|---------|
| `index.faiss` | FAISS-индекс векторов |
| `index.pkl` | Сериализованное хранилище документов: маппинг ID чанков на текст и метаданные |

Индекс строится автоматически при первом запуске, если его нет. Он **не обновляется автоматически**: после изменения любого файла из `data/`, который попадает в индекс (`.md`-файлы и `assignments.csv`), индекс устаревает. Для ручного пересоздания удалите `storage/faiss_index/` и перезапустите приложение.

## 6. Поток поиска

```
Вопрос студента
       │
       ▼
OpenAI Embeddings API
(эмбеддинг вопроса)
       │
       ▼
FAISS similarity_search()
(IndexFlatL2, L2-расстояние, top_k=4 по умолчанию, без порога)
       │
       ▼
Найденные чанки
(текст + метаданные для каждого)
       │
       ▼
Вопрос о дедлайнах/заданиях?  ── да ──▶  данные assignments.csv
(поиск ключевых слов)                    читаются напрямую и ставятся
       │                                 в начало списка чанков
       ▼
Сборка контекста
(объединение текстов, сбор имён найденных материалов)
       │
       ▼
Построитель промпта
(подстановка контекста + learner_level в системный промпт)
       │
       ▼
OpenAI Chat API
(gpt-4o-mini по умолчанию)
       │
       ▼
Ответ + список найденных материалов отображаются в UI
```

### Найденные материалы и цитаты

Блок «Источники» в UI строится из метаданных всех чанков, переданных модели в контексте (`format_context()`). Это список **найденных материалов**, а не проверенных ссылок: код не определяет, какие из них модель действительно использовала в ответе. Строку `*Источники: …*`, которую системный промпт просит добавить в конце ответа, пишет сама модель, и она не сверяется с контекстом. Тот же список сохраняется в колонку `retrieved_sources` журнала запросов.

## 7. Параметры поиска

| Параметр | По умолчанию | Env-переменная | Описание |
|----------|-------------|----------------|---------|
| `top_k` | 4 | `RAG_TOP_K` | Количество извлекаемых чанков |
| Модель | `gpt-4o-mini` | `OPENAI_MODEL` | LLM для генерации ответа |
| Эмбеддинги | `text-embedding-3-small` | (задано в коде) | Модель эмбеддингов |

## 8. Добавление новых документов

Чтобы добавить новый документ в базу знаний:

1. Создайте `.md`-файл в `data/` с блоком метаданных в начале
2. Удалите `storage/faiss_index/` для принудительного пересоздания индекса
3. Перезапустите приложение — индекс будет пересоздан автоматически

Подробные инструкции — в `docs/update_guide.md`.

---

## 9. Ограничения

- Индексируются только `.md`-файлы в `data/` (без поддиректорий; `few_shot_examples.md` пропускается) и строки `assignments.csv`
- Пересоздание индекса требует перезапуска приложения (горячая перезагрузка не поддерживается)
- Нет гибридного поиска (ключевые слова + векторный) — только семантический; ключевые слова используются лишь для включения детерминированного пути с `assignments.csv`
- Нет порога релевантности: запрос всегда возвращает `top_k` чанков, даже слабо связанных с вопросом
- Качество поиска зависит от качества модели эмбеддингов
- Очень короткие или плохо написанные чанки могут плохо находиться
