# Архитектура промптов — EduCurator AI

## Обзор

Этот документ описывает дизайн промптов для AI-ассистента EduCurator: роль ассистента, сценарии диалогов, ограничения, адаптацию к уровню студента и статус few-shot примеров. Сам текст системного промпта находится в `src/prompt_builder.py` (см. `docs/system_prompt.md`).

---

## 1. Роль ассистента

EduCurator — это **ассистент поддержки курса**, а не учитель, не репетитор и не администратор. Его роль чётко ограничена:

| В компетенции | Вне компетенции |
|---------------|----------------|
| Объяснять концепции курса | Выставлять оценки |
| Отвечать на вопросы из FAQ | Менять дедлайны |
| Рекомендовать ресурсы | Получать доступ к данным студента |
| Описывать требования к заданиям | Решать задания за студента |
| Направлять к живой поддержке | Принимать административные решения |

Ассистент спроектирован как **первая точка контакта** для студентов — до обращения к куратору-человеку.

---

## 2. Структура промпта

Каждый запрос к LLM состоит из трёх частей:

```
[Системный промпт]
  └─ Определение роли
  └─ Инструкция по уровню студента
  └─ Найденный контекст курса (RAG)
  └─ Правила поведения и ограничения

[Сообщение пользователя]
  └─ Вопрос студента (как введён)

[Ответ ассистента]
  └─ Ответ, основанный на материалах курса
  └─ Строка источников (пишется самой моделью)
  └─ Эскалация при необходимости
```

Системный промпт собирается динамически в `src/prompt_builder.py` путём подстановки:
1. `{learner_level}` — «beginner» или «advanced», выбирается студентом
2. `{context}` — материалы, найденные по запросу: чанки из FAISS-индекса, а для вопросов о дедлайнах и заданиях — ещё и данные `assignments.csv`, поставленные в начало контекста

История диалога в запрос не передаётся.

## 3. Основные сценарии

### Сценарий А: Объяснение концепции

**Триггер:** студент спрашивает «Что такое chain-of-thought промптинг?»
**Пайплайн:**
1. RAG находит чанки из `modules.md` (Модуль 3) и `resources.md`
2. Системный промпт задаёт тон в зависимости от уровня
3. LLM объясняет концепцию, опираясь на найденный материал
4. Промпт просит модель указать источники в конце ответа

### Сценарий Б: Вопрос о дедлайне

**Триггер:** студент спрашивает «Когда дедлайн по заданию модуля 4?»
**Пайплайн:**
1. Слова вопроса («дедлайн», «задани», «модуль» и т. п.) включают детерминированный путь: из `assignments.csv` читается строка модуля 4 (если номер в вопросе не распознан — краткий список всех заданий) и ставится в начало контекста
2. Семантический поиск в FAISS добавляет top-K чанков, например из `faq.md` с политикой опозданий
3. Раздел промпта «Дедлайны и задания» требует брать дату в формате `ГГГГ-ММ-ДД` из данных `assignments.csv` как единственный источник истины
4. Ответ содержит дедлайн и, при наличии в контексте, политику опозданий

### Сценарий В: Рекомендация ресурсов

**Триггер:** студент спрашивает «Что почитать, чтобы глубже изучить RAG?»
**Пайплайн:**
1. RAG находит чанки из `resources.md`
2. Системный промпт применяет фильтр уровня (beginner / advanced)
3. LLM рекомендует подходящие ресурсы с пояснением

### Сценарий Г: Запрос вне компетенции

**Триггер:** студент просит «Измени мою оценку»
**Пайплайн:**
1. RAG находит несколько ближайших чанков (возможно, FAQ об оценках)
2. LLM применяет правила ограничений из системного промпта
3. Ответ вежливо отклоняет запрос и направляет к куратору-человеку

### Сценарий Д: Неизвестная тема

**Триггер:** студент спрашивает о чём-то, чего нет в базе знаний
**Пайплайн:**
1. FAISS всегда возвращает top-K ближайших чанков: порога релевантности нет, поэтому в контекст попадают слабо связанные материалы
2. Решение «в материалах этого нет» принимает LLM по инструкции из промпта
3. Ожидаемый ответ: «В материалах курса я не нашёл информации по этому вопросу», затем помощь по смежным темам или совет обратиться к куратору

## 4. Ограничения и защитные правила

Системный промпт явно запрещает:

1. **Запрет галлюцинаций** — «не выдумывай информацию вне материалов курса»
2. **Запрет обещать результат** — «не обещай зачёт, сертификат или конкретную оценку»
3. **Запрет менять дедлайны** — «не меняй дедлайны»
4. **Запрет решать задания** — «не давай прямых ответов на задания»
5. **Источники** — «указывай источники, если использованы материалы курса»
6. **Эскалация** — определены условия передачи вопроса куратору-человеку

Эти ограничения — инструкции модели, а не программные проверки. Автоматических тестов на их соблюдение нет; проверка выполняется вручную по сценариям из `README.md`. Строка источников в ответе пишется самой моделью и не сверяется с контекстом; блок «Источники» в UI показывает найденные материалы, а не подтверждённые цитаты.

## 5. Адаптация под уровень студента

Ассистент адаптирует ответ на основе параметра `learner_level`:

### Режим «Начинающий» (beginner)
- Использовать простой язык, избегать жаргона
- Давать аналогии и примеры из жизни
- При первом употреблении определять технические термины
- Больше поддержки и ободрения
- Рекомендовать ресурсы из раздела «Для начинающих» в `resources.md`
- Ответы короче и сфокусированнее

### Режим «Продвинутый» (advanced)
- Свободно использовать техническую терминологию
- Пропускать базовые определения
- При необходимости ссылаться на научные статьи
- Предлагать сложные ресурсы и фреймворки
- Признавать тонкости и компромиссы в тематике
- Допускать упоминание ограничений и открытых исследовательских вопросов

Уровень подставляется в системный промпт через переменную `{learner_level}`. Часть перечисленного выше — ожидаемое поведение; в самом промпте для каждого режима заданы лишь краткие инструкции (простой язык и аналогии для beginner, терминология и углублённые ресурсы для advanced).

## 6. Few-shot примеры

Few-shot блок в запросы к API **не передаётся**, и файл `data/few_shot_examples.md` **не загружается** в системный промпт. Файл также исключён из FAISS-индекса (`SKIP_FILES` в `src/rag_pipeline.py`), поэтому не попадает и в `{context}`.

Сейчас файл — справочный материал: он фиксирует примеры желаемого и нежелательного поведения ассистента и может служить ориентиром при ручной проверке и доработке промпта. На поведение приложения во время работы он не влияет, и им не подтверждается, что ассистент ведёт себя именно так.

Если когда-нибудь понадобится реальный few-shot, примеры придётся подключить в `src/prompt_builder.py`; сейчас этого нет.

## 7. Бюджет токенов

Грубая оценка (не измерение) распределения токенов на один запрос:

| Компонент | Примерное число токенов |
|-----------|------------------------|
| Системный промпт (шаблон, включая инструкции по уровню, без контекста) | ~900 |
| RAG-контекст (4 чанка до 800 символов, ~300 токенов каждый) | ~1 200 |
| Вопрос студента | ~50–150 |
| **Итого вход** | **~2 150–2 250** |
| Ответ (потолок `max_tokens=800`, ориентир ~300–600) | ~300–600 |
| **Итого на запрос** | **~2 450–2 850** |

Для вопросов о дедлайнах и заданиях вход вырастает на данные из `assignments.csv`. Стоимость запроса с `gpt-4o-mini` — порядка десятых долей цента; точная цифра зависит от текущих тарифов.

---

## 8. Известные ограничения

- Ассистент не имеет памяти между запросами и сессиями (без сохранения состояния)
- Все знания статичны — база знаний требует ручного обновления
- Качество RAG-поиска зависит от качества чанков и сходства эмбеддингов
- Нет порога релевантности: в контекст всегда попадает top-K чанков
- Соблюдение правил промпта зависит от модели и не покрыто автоматическими тестами
- Блок «Источники» в UI — найденные материалы, а не проверенные цитаты
- Ассистент не может верифицировать личность студента или получить доступ к данным платформы
- Адаптация уровня основана на самооценке студента, а не на реальном тестировании
