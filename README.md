# EduCurator AI — RAG-ассистент поддержки учебного курса

Компактная демонстрационная реализация RAG-ассистента для поддержки студентов вымышленного курса **«AI Skills Starter Course — стартовый курс по AI-инструментам и prompt engineering»**. Streamlit, OpenAI, LangChain, FAISS.

---

## О проекте

Проект показывает, как собрать небольшого ассистента для **операционной поддержки курса**: ответы по материалам, организационные вопросы (дедлайны, задания, FAQ), подбор ресурсов и передача сложных случаев человеку. «Куратор» здесь — человек, который сопровождает студентов курса.

- Работает на небольшой статичной базе знаний вымышленного курса: четыре Markdown-файла и CSV с заданиями.
- Сфокусирован на поддержке курса, а не на персональном обучении.

Чем проект **не** является:

- универсальным мультимодальным учебным ассистентом — только текст и только русский язык;
- платформой учёта прогресса студентов — нет профилей, истории диалогов и данных об успеваемости;
- системой курирования или рекомендации контента — ресурсы берутся из статичного `resources.md`, рекомендательной логики нет;
- заменой LMS и production-системой — нет интеграции с LMS, авторизации и автоматических тестов.

### Что здесь технически интересного

- **Семантический RAG** по материалам курса: чанкинг, эмбеддинги OpenAI, локальный FAISS-индекс.
- **Детерминированная работа со структурированными данными.** Для вопросов о дедлайнах и заданиях данные `assignments.csv` читаются напрямую и ставятся в начало контекста; те же строки дополнительно входят в FAISS-индекс.
- **Границы роли и эскалация.** Системный промпт запрещает менять дедлайны и оценки, решать задания за студента и выдумывать факты; задаёт формулировку «в материалах нет информации» и контакт куратора-человека. Поведение задаётся промптом и проверяется вручную (см. сценарии ниже).
- **Аналитика для куратора.** Каждый вопрос попадает в CSV-журнал; вкладка «Аналитика» показывает распределение вопросов по уровню и теме.

### Демо-данные

Курс, задания, дедлайны и адрес куратора вымышлены. Даты в `data/assignments.csv` (июнь–июль 2026) заданы статично, на момент чтения могут быть в прошлом, а ассистент не сверяет их с текущей датой.

## Функциональность

| Функция | Описание |
|---------|---------|
| **RAG Q&A** | Ответы на вопросы с опорой на проиндексированную базу знаний курса |
| **Структурированные данные о заданиях** | Для вопросов о дедлайнах и заданиях данные `assignments.csv` добавляются в контекст детерминированно |
| **Адаптация к уровню** | Подстройка сложности ответа под самостоятельно выбранный уровень (начинающий / продвинутый) через системный промпт |
| **Найденные материалы** | После ответа UI показывает список материалов, найденных и переданных модели в качестве контекста (блок «Источники») |
| **Вкладка «Курс»** | Описание курса и таблица заданий с дедлайнами |
| **Вкладка «Аналитика»** | Статистика запросов: всего, по уровню, по теме, последние вопросы |
| **Логирование** | Каждый вопрос записывается в `logs/query_log.csv` |
| **Отказ и эскалация** | Системный промпт предписывает признавать отсутствие информации и направлять к куратору-человеку; поведение не покрыто автоматическими тестами |

## Как запустить локально

### 1. Клонировать или скачать проект

```bash
git clone <repo-url>
cd edu-curator-rag-assistant
```

### 2. Создать виртуальное окружение

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# macOS/Linux
source venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Создать файл `.env`

```bash
cp .env.example .env
```

Отредактируйте `.env` и добавьте ваш ключ OpenAI API:

```
OPENAI_API_KEY=sk-ваш-реальный-ключ
OPENAI_MODEL=gpt-4o-mini
RAG_TOP_K=4
```

### 5. Запустить приложение

```bash
streamlit run app.py
```

Приложение откроется по адресу `http://localhost:8501`.

При первом запуске FAISS-индекс построится автоматически (~15–30 секунд).

## Как обновить базу знаний

1. Отредактируйте `.md`-файлы в `data/` или измените строки в `data/assignments.csv`
   (в `.md`-файлах сохраняйте блок метаданных в начале)
2. Удалите `storage/faiss_index/` для принудительного пересоздания индекса:
   ```powershell
   # Windows PowerShell
   Remove-Item -Recurse -Force storage\faiss_index\
   ```
   ```bash
   # macOS/Linux
   rm -rf storage/faiss_index/
   ```
3. Перезапустите приложение — индекс пересоздастся автоматически (~15–30 сек)

> **Важно:** `assignments.csv` входит в FAISS-индекс, поэтому после его изменения (например, обновления дедлайнов) индекс нужно пересоздать так же, как после правки `.md`-файлов. Вкладка «Курс» и детерминированный путь для вопросов о дедлайнах читают CSV напрямую и видят новые данные сразу, но устаревшие строки в индексе могут продолжать попадать в контекст через семантический поиск.
>
> `data/few_shot_examples.md` в индекс не входит — его правка пересоздания индекса не требует.

Подробности — в `docs/update_guide.md`.

## Как работает RAG

### Построение индекса

При построении индекса используются два типа источников:

**Markdown-файлы** из `data/` (кроме `few_shot_examples.md`):
- разбиваются на чанки через `RecursiveCharacterTextSplitter`: размер чанка 800 **символов**, перекрытие 100 символов (длина считается в символах, не в токенах)
- метаданные берутся из заголовка файла: `source`, `resource_type`, `module`, `topic`

**`data/assignments.csv`** — LMS-заглушка с заданиями и дедлайнами:
- каждая строка преобразуется в отдельный `Document` (на чанки не разбивается)
- текст содержит модуль, задание, дедлайн, статус и описание в читаемом виде
- метаданные:

| Поле | Значение |
|------|---------|
| `source` | `assignments.csv` |
| `resource_type` | `lms_stub` |
| `topic` | `deadlines` |
| `module` | значение колонки `module` |
| `assignment` | значение колонки `assignment` |

Все документы встраиваются с помощью `text-embedding-3-small` и сохраняются в `storage/faiss_index/`. Индекс — `IndexFlatL2` из FAISS: точный поиск полным перебором по евклидову (L2) расстоянию, чем меньше расстояние, тем ближе чанк к вопросу.

### Retrieval при вопросе

1. Вопрос студента встраивается тем же эмбеддингом
2. Из FAISS-индекса извлекаются top-K ближайших чанков (по умолчанию 4). Порога релевантности нет — запрос всегда возвращает K чанков, даже если они слабо связаны с вопросом
3. **Приоритетный контекст:** если вопрос содержит слова о дедлайнах или заданиях (`дедлайн`, `срок`, `задани`, `сдать`, `модуль` и др.), данные из `assignments.csv` читаются напрямую и ставятся в начало контекста, перед найденными чанками: строка конкретного модуля, если номер (1–6) распознан в вопросе, иначе — краткий список всех заданий. Так точные даты гарантированно попадают в контекст модели
4. Все материалы объединяются и подставляются в системный промпт как `{context}`
5. LLM генерирует ответ (`temperature=0.3`, `max_tokens=800`), опираясь на переданный контекст
6. UI показывает ответ и блок «Источники» — список материалов, которые были найдены и переданы модели (файл и тема). Это именно найденные материалы: UI не проверяет, какие из них модель реально использовала. Строка `*Источники: …*`, которую промпт просит добавить в конце ответа, пишется самой моделью и тоже не сверяется с контекстом

Полная схема — в `docs/rag_schema.md`.

## Как работает логирование и аналитика

- Каждый вопрос добавляется в `logs/query_log.csv` (создаётся автоматически)
- Записываемые поля: `timestamp`, `question`, `learner_level`, `retrieved_sources`, `answer_preview`, `topic_guess`
- `retrieved_sources` — найденные материалы (как в UI), `answer_preview` — первые 200 символов ответа
- `topic_guess` определяется по ключевым словам (простая эвристика, не классификатор): дедлайны, задания, rag, промпты, ресурсы, общее
- Вкладка **«Аналитика»** читает этот файл и отображает:
  - Общее количество вопросов
  - Разбивку по уровню студента
  - Разбивку по теме
  - Последние 10 вопросов
- Авторизации нет: вкладка доступна всем, кто открыл приложение

## Направления развития (не реализовано)

Ничего из этого списка в текущей версии нет:

- **Интеграция с LMS**: реальные данные о курсах, заданиях и дедлайнах через API вместо локального CSV-файла.
- **Авторизация и роли пользователей**: разделить доступ для студентов, кураторов и администраторов.
- **История диалога и персонализация**: учёт предыдущих вопросов, уровня подготовки и прогресса по модулям.
- **Админ-интерфейс для обновления базы знаний**: загрузка новых материалов и переиндексация без ручного удаления FAISS-индекса.
- **Расширенная аналитика**: частые темы, проблемные модули, повторяющиеся запросы.
- **Дополнительные каналы**: Telegram-бот, виджет для сайта.
- **Контроль качества ответов**: набор тестовых вопросов, регулярная проверка ответов, метрики retrieval/generation, проверка того, что ответ действительно опирается на найденные источники.
- **Эскалация к человеку**: сейчас это лишь указание в промпте назвать контакт куратора; автоматическое формирование обращения не реализовано.

## Ограничения

- Ассистент **не помнит** предыдущие диалоги — каждый вопрос независим
- База знаний **статична** — изменения требуют ручного пересоздания индекса
- **Нет авторизации** — любой, у кого есть доступ к URL, может использовать ассистента и открыть аналитику
- **Нет реальной LMS-интеграции** — дедлайны и задания — вымышленные данные в CSV, ассистент не сверяет их с текущей датой
- **Нет порога релевантности** — в контекст всегда попадает top-K чанков; отказ «информации нет» зависит от модели и промпта
- **Нет автоматических тестов и оценки качества** — поведение проверяется вручную по сценариям ниже
- **Блок «Источники» показывает найденные материалы**, а не подтверждённые цитаты
- `data/few_shot_examples.md` — справочный материал, в рантайме не используется
- **Уровень студента** основан на самооценке, а не на реальном тестировании
- **Только русский язык** — база знаний и промпты на русском
- Стоимость API: ориентировочно $0.001–0.003 за вопрос при использовании gpt-4o-mini (оценка, не измерение)

## Демо-сценарии для ручной проверки

Задайте эти вопросы в приложении, чтобы увидеть ожидаемое поведение. Автоматических тестов нет, а ответы LLM недетерминированы, поэтому формулировки будут отличаться.

### Объяснение концепций (уровень «Начинающий»)

> «Что такое токен? Объясни простыми словами.»

Ожидаемое поведение: понятное объяснение с аналогией, без жаргона. Среди найденных материалов — `modules.md`.

> «Я новичок. Объясни, что такое RAG и зачем он нужен.»

Ожидаемое поведение: доступное объяснение Retrieval-Augmented Generation с примером. Среди найденных материалов — `modules.md`.

### Углублённый запрос (уровень «Продвинутый»)

> «Я продвинутый студент. Какие дополнительные материалы посмотреть по RAG?»

Ожидаемое поведение: ссылки на статьи (Lewis et al. 2020), LlamaIndex, RAGAS из `resources.md`. Технический тон ответа.

### Вопросы о дедлайнах и заданиях

> «Когда дедлайн по заданию модуля 4?»

Ожидаемое поведение: ответ с датой **2026-07-05** (вымышленная демо-дата) из `assignments.csv`. В списке найденных материалов — `assignments.csv (deadlines)`.

> «Что делать, если я не успеваю сдать задание вовремя?»

Ожидаемое поведение: описание окна опозданий (3 дня, −10%/день), инструкция по запросу переноса, email куратора. Среди найденных материалов — `faq.md`.

### Проверка границ: информация вне базы знаний

> «Кто ведущий преподаватель курса?»

Ожидаемое поведение: «В материалах курса я не нашёл этой информации» + предложение обратиться к куратору. Без выдуманных имён.

### Проверка ограничений ассистента

> «Можешь изменить мне дедлайн по заданию?»

Ожидаемое поведение: вежливый отказ («я не могу менять дедлайны»), инструкция написать куратору минимум за 24 часа.

> «Поставь мне зачёт за модуль 2.»

Ожидаемое поведение: вежливый отказ («я не выставляю оценки»), объяснение как работает оценивание, направление к куратору.
